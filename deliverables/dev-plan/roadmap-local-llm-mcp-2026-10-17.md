# GLM-Chat 本地大模型接入 + MCP 优化 · 迭代路线图

**日期**：2026-10-17
**类型**：迭代路线图（可落地版）
**基线**：v1.4.0「体验版」（2026-10-17 已打包交付：22.6MB onefile，VERSION=1.4.0；其 MCP callTimeout 每服务器可配（F2）/ 压缩透明化（UX-1）/ estTokens 修复（TOK-2）三项前置已随包落地）
**范围**：分阶段集成本地大模型（Local LLM）支持 + MCP 模块稳定性/速度专项优化
**状态**：v1.0（待产品负责人审定）

---

## 📌 TL;DR

- **一句话**：用两个版本周期把 GLM-Chat 从「云端 BYOK 客户端」扩展为「云端 + 本地双模客户端」，再用一个专项周期把 MCP 模块的连接开销打下来——全部改造**零第三方依赖、不动 js_api 契约、不碰打包配置**。
- **版本序列**：v1.4.0 体验版（已规划，13.5 人日，含本路线图前置项）→ **v1.5.0 本地模型**（连接层 A + 适配层 B，12.5 人日）→ **v1.5.1 MCP 专项**（5.5 人日）→ v1.6.0 WebDAV（从 v1.4 推迟至今，10–20 人日，独立 PRD）。
- **重排序说明**：roadmap 原定 v1.5 = 数据主权。本次按产品负责人指示调整为「本地模型优先」——理由：本地模型有明确生态窗口（Ollama/LM Studio 用户基盘扩张，竞品 5ire 已支持 Ollama），且接入路径可完全复用 v1.2 R6 provider 抽象，风险低于 WebDAV 的冲突合并设计；WebDAV 顺延 v1.6 并保留独立设计周期。
- **总工程量**：v1.5.0 + v1.5.1 共 18 人日；单人全职约 4 周 / 2 人并行约 2.5–3 周。

## 🎯 核心结论卡片

| 项目 | 内容 |
|------|------|
| 本地模型路线 | 连接层（A：预设/探测/清单/本地计费）→ 适配层（B：上下文感知/工具能力降级/慢推理/Ollama 特情） |
| 架构决策 | **只做「连接」不做「内嵌推理」**——内嵌 llama.cpp 类运行时与零依赖/onefile/Python 3.10 三条铁律全冲突；本地服务器（Ollama/LM Studio/vLLM/llama.cpp）均暴露 OpenAI 兼容端点，复用 R6 provider 抽象即可 |
| MCP 专项两大刀 | ① HTTP 传输连接复用（现每次调用新建 TCP+TLS，urllib 无 keep-alive）→ P95 -40%；② stdio 温启 + 崩溃恢复加固 → 首调用延迟 -80% |
| 性能验证 | 本地回环自建 MCP HTTP 服务器可在**本开发环境**跑真实基准（无需外网）；真实 Ollama/模型质量验证需目标机 |
| 风险等级 | 中——本地生态碎片化（能力/窗口差异大）、连接池改造的安全回归、上下文窗口误判致请求失败 |

## 1. 现状实测（路线图设计依据，2026-10-17 代码库核实）

| 事实 | 位置 | 对路线图的含义 |
|---|---|---|
| provider 抽象已存在：GLM 默认 + 单活自定义 OpenAI 兼容端点（Base URL/Key/模型/价格），配置存 config.json `provider_*` 键（save_config 合并，契约不受影响） | `71-provider.js`、`provider_service.py` | 本地模型 = 新 preset + 探测 + 适配，**不需要新 provider 体系**；本地模式新键沿用 `local_*` 同款模式 |
| `test_endpoint` 强制要求 API Key | `provider_service.py:45` | 本地服务器通常无鉴权，需 local 标志跳过 Key 校验 |
| MCP HTTP 传输每次调用 `urlopen_no_redirect` 新建请求，**无连接复用**（urllib 无 keep-alive），HTTPS 每次全量 TLS 握手 | `mcp_transport_http.py:92-100` | HTTP MCP 调用最大性能刀口；改 `http.client` 连接池（stdlib，零新增依赖） |
| MCP `tool_schemas()` 为零 IO 缓存读（`_rt` 缓存 + list_changed 失效） | `mcp_service.py:173` | schema 缓存**已优化到位**，专项不再碰 |
| stdio 空闲回收 600s（IDLE_TIMEOUT）、崩溃自动重 spawn 一次、404 会话重连一次均已实现 | `mcp_service.py` | 稳定性底子好；专项做温启、stale 检测、重连退避 |
| 超时体系：CALL=60（v1.4 F2 起每服务器可配 10–300）/ CONNECT=30 / LIST=15 / IDLE=600 | 同上 | 本地模型驱动的慢工具调用已有配置通道（v1.4 前置项） |
| Agent 主链路 fetch **无客户端硬超时**（无 AbortSignal.timeout） | `60-agent-loop.js` | 本地 CPU 推理首 token 30–60s 不会被误杀——好底子；补 idle watchdog 即可 |
| 自动压缩阈值为固定 token 数（45k/90k/140k 三档） | `40-auto-compact.js` | 本地模型常见 4k–32k 窗口，固定阈值会直接超窗失败 → 必须改「按模型窗口比例」 |

## 3. Cycle 1 · v1.5.0 连接层 A（6 人日）

**目标**：用户能在 3 步内（选预设 → 探测/选模型 → 测试连接）把本地服务器接入，且计费显示正确切换为「本地 · 零费用」。

### 3.1 任务表

| # | 任务 | 内容 | 工作量 |
|---|---|---|---|
| A1 | **本地端点预设** | provider 预设新增：Ollama（`http://localhost:11434/v1`，模型如 `qwen2.5:7b`）、LM Studio（`http://localhost:1234/v1`）、vLLM（`http://localhost:8000/v1`）、llama.cpp server（`http://localhost:8080/v1`）、LocalAI。预设一键填充 base_url + 价格清零 + local 标志 | 1.0 |
| A2 | **本地服务器探测** | 后端 `local_probe()`：对 11434/1234/8000/8080 四端口**并行**探测（各 2s 超时，总墙钟 ≤1s），命中则尝试 `GET {base}/models` 解析模型清单；返回 `{reachable:[{base_url,kind,models[],latency_ms}]}`。走 `urlopen_no_redirect`（复用 S15 安全口径，localhost 免 Key） | 1.5 |
| A3 | **模型清单选择 + 元数据表** | 探测成功 → 模型下拉选择替代手输；内置本地模型元数据表（ctx_window / tool_capable / 资源提示）：qwen2.5 系 32k、llama3.1 系 128k/8b 档 8k 变体、mistral 7b 32k、deepseek-r1 蒸馏系 64k、gemma2 8k……未知模型给保守默认 8k + 「可手动改」 | 1.5 |
| A4 | **本地模式计费与速度显示** | 会话头部「约花费 ¥X」在 local 模式切为「本地 · 0 费用」；流式期间显示 tokens/s（usage 到达即算，无 usage 的本地服务器按字符估算并标注「估」）；75-token-stat 三价计算对本地短路（价格 0 不查表） | 1.0 |
| A5 | **测试连接增强** | `provider_test_endpoint` 加 `local` 参数：跳过 Key 校验；超时默认延长至 30s；识别「模型冷启动加载中」（Ollama 首问 10–60s）→ 返回 loading 态而非失败 | 1.0 |

### 3.2 接口设计要点

- **新增 js_api（全部登记 `_V12_EXTRA` 隐身）**：`local_probe()`（并行探测+模型清单）、`local_models(base_url)`（补拉清单，探测过期时用）。复用 `provider_test_endpoint` 加 `local` 标志——**不新建测试通道**。
- **config.json 新键**（运行期合法、测试期不触发——v1.2 同款模式）：`local_mode`(bool) / `local_base_url` / `local_model` / `local_ctx_window`(int，用户覆盖) / `local_tool_capable`(auto/on/off)。
- **provider_state 扩展而非新建**：单活端点模式不变（GLM ⇄ 本地切换即关/开 provider + local 标志），避免多端点体系的大改。
- **不新增传输层**：本地模型走前端 fetch → 本地服务器，与自定义端点同链路。

### 3.3 性能优化目标

| 指标 | 目标 | 验证方式 |
|---|---|---|
| 探测总耗时 | ≤1s（4 端口并行，单端口 2s 超时） | 单测打桩计时 + 目标机实测 |
| 模型清单获取 | ≤3s | 同上 |
| 测试连接（模型已驻留） | ≤5s 返回 | 打桩 |
| 测试连接（冷启动） | ≤90s 返回 loading 态 + 进度提示，不报错 | 打桩 503 序列 |

### 3.4 测试验证

`tests/test_v15_local.py`：探测并行打桩（mock urlopen 按端口分派：活/死/超时三种）、models 解析（Ollama/LM Studio/vLLM 三种响应形态）、preset 表完整性（URL 格式/价格清零/local 标志）、local 测试连接（无 Key/loading 态/失败态）、契约差分（新键不进测试 config）、UI 契约（新增 DOM 只增不改）。

## 4. Cycle 2 · v1.5.0 适配层 B（6.5 人日）

**目标**：本地模型接入后**真正可用**——不超窗、能力不符时优雅降级、慢推理有可见反馈。这一层是「能连」到「好用」的分水岭。

### 4.1 任务表

| # | 任务 | 内容 | 工作量 |
|---|---|---|---|
| B1 | **上下文窗口自适应** | `autoCompactThreshold` 从固定 token 值改为「模型 ctx_window × 60%」（GLM 128k → 77k 与现标准档 90k 量级衔接；本地 8k 模型 → 4.8k 提前压缩）；窗口来源 = 元数据表 → 用户配置覆盖 → 默认 8k 三级；压缩档位（激进/标准/宽松）改为比例系数（0.4/0.6/0.8）叠加在窗口上 | 1.5 |
| B2 | **工具能力检测与降级** | 请求带 tools 时若端点返回 400 且错误体含 tool/function 不支持特征 → **自动去掉 tools 重发一次**（记一条 toast「当前模型不支持工具调用，已切换为纯对话模式」）；`local_tool_capable=off` 时根本不发 tools；UI 状态区明示「工具不可用（模型能力）」——MCP 工具面同步隐藏（tool_schemas 在 local 且不支持时返回空） | 2.0 |
| B3 | **慢推理适配** | 流式首字节等待态：>5s 未收首 chunk 显示「本地推理中（已等待 Ns）」每秒更新；idle watchdog：流中间 >120s 无字节 → 提示不断流（防病态服务器挂死）；本地模式默认建议 max_tokens 4096（现默认 16384，本地小窗口模型输出占比要克制） | 1.5 |
| B4 | **Ollama 特情处理** | 503「model is loading」→ 指数退避重试（2s/4s/8s，上限 120s，期间 loading 态可见）；404「model not found」→ 人话引导回模型清单重选；这两种错误码进 `humanize_http_error` 本地分支 | 1.0 |
| B5 | **本地模式 MCP 保守策略** | 本地模型工具调用参数幻觉风险高 → local 模式 + MCP 工具确认框追加提示文案「本地模型生成的工具参数未经云端模型校验，请仔细核对」；会话信任对 MCP 工具在 local 模式下降级为仅本任务有效（跨任务重新确认） | 0.5 |

### 4.2 接口设计要点

- **无新 js_api**：B 层全前端 + provider 配置键 + 既有 test_endpoint 扩展。
- **系统提示词**：`build_system_prompt` 在 local 模式追加一段（本地模型能力提示：上下文有限、工具不可用时如实说明）——该方法输出**不在**契约逐字节比对清单（比对的是 `get_api_info`/`build_tools`），安全；仍保持克制，仅 local 模式追加。
- **降级重试的边界**：自动重试仅一次且仅限「带 tools 的 400」特征错误；其他 400 不重试（防病态端点诱导风暴）；重试去掉的是 tools 字段，messages 原样。

### 4.3 性能优化目标

| 指标 | 目标 | 验证方式 |
|---|---|---|
| 上下文超窗失败率 | 0（阈值自适应 + 超窗错误人话兜底） | 打桩 400 context length → 走人话映射不崩 |
| 不支持 tools 模型降级成功率 | 100%（一次重试内） | mock 400 序列单测 |
| Ollama 503 加载重试成功率 | ≥90%（120s 上限内） | mock 退避序列单测 |
| 首 token 等待可见性 | >5s 即显示，每秒刷新 | vm harness 前端测试 |

### 4.4 测试验证

`test_v15_adapt.py`：ctx 阈值计算（5 个模型窗口 × 3 档位矩阵单测）、降级重试路径（带 tools 400 → 去 tools 重发 → 成功/再失败两分支）、503 退避时序（mock sleep 记录调用序列）、本地模式 MCP 确认文案与信任降级、estTokens 回归（不动 A2 豁免规则）。前端 vm harness：loading 态渲染、tool 不可用徽标。

## 5. Cycle 3 · v1.5.1 MCP 稳定性与速度专项（5.5 人日）

**目标**：MCP 模块 P95 调用延迟 -40%（HTTP）、首调用延迟 -80%（stdio 温启）、崩溃恢复用户可见 <3s。前置：v1.4 F2 超时可配已落地。

### 5.1 任务表

| # | 任务 | 内容 | 工作量 |
|---|---|---|---|
| S1 | **HTTP 连接复用（最大刀）** | `mcp_transport_http` 从「每请求 urlopen 新建连接」改为 `http.client.HTTPConnection`/`HTTPSConnection` 连接池：per host:port 复用、keep-alive、空闲 60s 回收、TLS 会话复用（HTTPS 每次全量握手是本地回环以外的主要开销）。**安全口径全保留**：no-redirect（S15）、协议头强制覆盖（⑫）、Mcp-Session-Id 回收、64KB 响应上限（㉒）、SSE 增量读（S14）逐条移植到新路径并加对应用例 | 2.5 |
| S2 | **stdio 温启** | 启用服务器即预热 spawn（test_server 成功的 client 转 warm entry 保留，IDLE 600s 已有机制兜底回收）；状态面板显示「已预热 / 冷启耗时 Nms」；首调用延迟打点（spawn→ready） | 1.0 |
| S3 | **恢复与一致性加固** | list_changed 后 300s 未刷新 → 自动 relist（stale 检测）；HTTP 404 会话重连加次数上限（3 次）+ 退避（1s/2s/4s），防抖防风暴；崩溃重 spawn 已有（v1.3）——补「重 spawn 也失败 → 状态灯红 + 一键重试」入口 | 1.0 |
| S4 | **审计延迟测量（先测后优）** | `_audit` 每次同步 append（信任版语义保留）；加 P95 延迟打点（单测桩计时）。若 P95 >20ms 再上「异步队列 + 退出 flush + 每 N 条或 T 秒落盘」——**测量不过线就不改**，审计 durability 是信任资产 | 0.5 |
| S5 | **并发上限** | HTTP 服务器并行 tools/call 并发上限默认 4（可配 `max_concurrency` 1–8）；stdio 单进程天然串行（确认已有锁串行化，补单测钉住）；超限排队而非拒绝（队列深度提示） | 0.5 |

### 5.2 接口设计要点

- `mcp_servers.json` 新增**可选**键（Claude 兼容结构忽略未知键，老配置文件零影响）：`keep_alive`(bool，默认 true) / `max_concurrency`(int 1–8，默认 4) / `warm_on_enable`(bool，默认 true)。
- 连接池对宿主替换 urlopen 的测试桩保持兼容（DI 接缝不变：`_STDLIB_URLOPEN` 捕获模式平移到 `http.client` 工厂）。
- 无新 js_api；配置读写走既有 `mcp_save_server`。

### 5.3 性能优化目标

| 指标 | 现状（实测推估） | 目标 | 验证方式 |
|---|---|---|---|
| HTTP MCP 调用 P95 延迟 | 每次新建 TCP(+TLS) | **-40%**（本地回环消除握手最明显；远端 HTTPS 省全量 TLS） | 本环境可测：127.0.0.1 自建 MCP HTTP 服务器（Python `http.server` + 规范端点）跑前后对比，P50/P95 记录归档 |
| stdio 首调用延迟 | 含 spawn+握手（npx 类 1–3s，uvx 0.5–1s） | **-80%**（温启后转为 ~0） | 打桩计时 + 目标机实测 |
| 崩溃恢复用户可见时间 | 重 spawn 一次（已有） | <3s（含状态反馈） | 集成测试（真子进程桩，既有 test_v13_mcp 模式） |
| 审计写入 P95 | 未测量 | 测量；>20ms 才优化 | 单测桩计时 |

### 5.4 测试验证

`test_v15x_mcp_perf.py`：连接池单测（复用命中/空闲回收/错误连接不污染池/池上限）、no-redirect 与协议头在池化路径的回归（S15/⑫ 用例移植）、SSE 增量读池化回归（S14/W16）、温启与崩溃恢复集成（真子进程）、并发上限与 stdio 串行化钉住、性能基准脚本（本地回环服务器 + 记录模板 → `deliverables/metrics/`）。

## 7. 横切工程纪律（每周期适用）
