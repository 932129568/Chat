## 6. 踩坑实录（M1-M2.7 实战摘要——接手避坑）

**测试层**（都是实证根因后修，勿再犯）：
1. **check() 无 `tier` 键**——预算 needs_confirm 最初按 check.action 判，受 armed/trusted/grant 影响误判 allow；**正解=按 guard 档位判**（always/session/listless）
2. **同文件 replace 连带误伤**——python 批量替换 TTL 断言时把 harness 模板里的同一行也改了（`#` 注释 JS 不认炸 node）——**同文件 replace 要防共享文本模式**
3. **计划 risk 值域是 l0/l2**（不是 read/mutate/dangerous；'dangerous' 会被既有 `[:4]` 截成 'dang'）
4. **refund 真实序列**：issue→consume（token 离 map）→refund；直接 issue→refund 会撞「已存在不覆盖」闸
5. **run_command 默认 off 档**不产生确认需求——测试选 always 档 op（delete_path）才能验预算越限
6. **`_OP_GRANT_SCOPES` 值是字符串**——`list()` 拆成字符，要 `_norm_scopes` 归一
7. **迁移=路径口径**：checkpoint_service 最初写 plans/checkpoints，旧数据在 CONFIG_DIR/checkpoints——**统一旧口径**
8. **replace 静默失败**——python `str.replace` 无匹配不报错，改完必须 grep 验证（本版三次中招：PlanService 无 `__init__` 导致装配没生效等）

**产品层**（bug 实录）：
- RSS 路径 `html=''` 时 `fetch` 未定义（HTML 结果处理块缩进）——RSS 是新增主路径，HTML 兜底必须零改
- tag_payload `source` dict 覆盖契约 `source='live'` 键——键冲突保护（契约键禁覆盖）
- api 装配顺序：search 先于 reader/hybrid——**依赖序：hybrid→reader→search**
- 400 剥除重试曾是死代码（`if not ok: return` 在重试逻辑之前）
