01

概述

版本目标与设计思路总纲。本版前端不是风格切换，而是 Harbor v4 设计体系内的增量升级：在既有玻璃拟态 + 编辑部排版基底上，把 v1.9.0「全域版」的五类新能力落成可移植的界面契约。

1.1 版本目标

Harbor v1.9.0「全域版」（单版本全量交付，不拆分）：① 补完 v1.8 路线图最后遗留（dual-LLM-lite 本地读取器等）；② 浏览器从「Windows 搜索专用」升级为 Win / macOS 双端通用 AI 驱动浏览器（六原语）；③ 完成 Harbor 整版 macOS 移植（平台服务 / UI / 安装器 / 打包公证分发）。

前端侧对应 1 个新模块 + 8 个改动模块（69-platform.js 新；26-guard.js / 66-plan.js / 67-plan-card.js / 39-search-panel.js / 34-local-model.js / 25-tool-exec.js / 60-agent-loop.js / index.template.html 改），外加审计视图 74-audit-view.js（新）。全部改动遵守一条铁律：UI 契约只增不改——新 DOM id / class 纯增，既有 40 id / 13 onclick / 43 callApi / 39 类 / 21 变量零改动。

2.2 令牌方案三维（彩格调）

设计系统专家据七项必做产出《设计令牌升级方案（彩格调）》——定位为 v4 体系内增量升级，双端一套令牌、平台差异化注入、UI 契约只增不改。三个维度：

维度要点

组件规范命名延续 v4 前缀（plan- / ckpt- / brw- / grant- / mac-）：计划卡升级（eta 徽标 / 风险条 / 边界声明 / 累计上下文 / 自动批准态）、检查点 inline 卡三态、浏览器面板（模式滑块 / 六原语行 / 反爬接管卡）、预算指示器（mono 计数 + 5 格 dot + 超限 err + 一键收回）、macOS 适配层（平台注入六件套 + 双映射键位 + 平台徽标 + mac 圆钮 switch）。

渲染状态纪律

方案附《v1.9 新令牌渲染状态表》区分「已渲染 / 留待挂载」：--skylight-strength（随对话区移植启用）、--bg-deep（原生窗口外圈，Web 原型无法呈现，需双端实测）、--edge-hi-strong（检查点禁模态叠模态，暂无挂载点）三项留待挂载，未强行渲染。方案另有 4 处勘误（暗态极光不透明度 / 滚动条宽度 / 控件圆角 / 光斑数）已按评审结论回写。

2.3 原型验证推导链

需求摘要 · 七项必做→ 令牌方案 · 彩格调三维→ 原型 6 文件 · 高保真→ 质量审查 · 五维 24/25 PASS→ 本交接报告

3.1 Intent Preview 计划卡 M2.3 / M2.5 · 66-plan.js 改 · 计划审查主关卡

「授权驱动替代弹窗驱动」的核心界面：用户发送后计划卡先行，批准才执行。单命令确认收缩到 deny + 高风险档，常规多步任务一律走计划审查。

  • 信息架构：头部 badge + 标题 + plan-eta 徽标（mono「≈3 步 · 2 分钟」）→ 步骤 checklist（既有五态 pending / doing / done / blocked / skipped）→ plan-riskbar 卡左侧 3px 风险色条（取最高步骤风险）→ plan-scope 边界声明区（dashed 边框，「将修改 / 不访问」双栏）→ 审计哈希链（prov-strip，虚线节点圆点）→ plan-ctx 累计上下文（mono 62% 细进度条）→ 三钮区：批准（primary + glow 白名单）/ 编辑（ghost）/ 拒绝（err-soft）。
  • 交互：批准进入两段式 anticipate 动效；L2 授权中且计划全 low 风险 → 自动批准态 plan-auto（ok 徽标「已自动批准 · 授权范围内」，3s 淡出）；拒绝 anticipate 收缩 + comp 淡出；UNTRUSTED 内容（外部来源数据）以琥珀 45° 斜纹边 + mono 来源 caption 标记，语义 = 内容可信度，区别于 err（操作失败）。
  • 动效链（批准）：press 90 → 三钮 comp-out 140 淡出 → badge pending→running 交叠（micro 130）→ steps stagger 60 入场 → eta micro 出场。高风险档禁快捷确认，仅 press 90 反馈、不抢跑。
  • 移植落点：66-plan.js（卡体升级）+ 60-agent-loop.js（计划审查主关卡分支）；计划卡 <30s 可扫、批准带累计上下文的渐进委托规格随 M2.5 落地。
打开原型：Intent Preview 计划卡 design/v19/prototypes/plan-intent-preview.html

3.2 检查点三态对话框 M2.7 / M2.8 · 67-plan-card.js 改 · 六军规 UI

任务执行中的「可后退」保障：计划卡内回滚链接进入，inline 卡三态流转，禁模态叠模态。

  • 信息架构（三态）：清单态 ckpt-list（stagger 40 逐项入场；文件行 ckpt-row 带 mod / add / del 徽标 + 大小 / 数量）→ 确认态（plan-rollback 回滚链接 + 确认钮，高风险档禁快捷确认）→ 校验态 ckpt-verify（ok / err 行 + 「已恢复至检查点 #N」）。
  • 交互：确认后按检查点差异恢复；校验提示淡入告知恢复结果；清单数据源为 checkpoints.json（新配置文件，保留 3 份，超限随创建清理）。
  • 动效链：回滚用 in-soft 200ms（收缩到位感，「后退用入场缓动」）；校验提示 narr 220 淡入（「前进用 out-soft」）；清单 stagger 40 封顶 160ms。
  • 移植落点：67-plan-card.js（检查点入口）；后端 checkpoint_service 六军规（差异恢复 / 绝不删未备份 / 自有影子仓库 / shell 前后快照 / 清单 + 确认 / 恢复后校验）随 M2.7 交付。
打开原型：检查点对话框 design/v19/prototypes/checkpoint-dialog.html

3.3 浏览器驱动面板 M3.8 / M5 · 39-search-panel.js 改 · 六原语

双端通用 AI 驱动浏览器的前端面孔：AI 后台驱动（隐藏）vs 用户可见浏览（可见）一键切换，六原语状态全程可见，反爬特征转人工接管。

  • 信息架构：brw-mode 可见 / 隐藏切换（spring 滑块 200ms）→ 可见模式弹出浏览器预览窗口 → brw-row ×6 六原语状态行（12px 状态点：ok 待命 warn 运行 err 失败，mono 耗时）→ 结果区（markdown 提取 + UNTRUSTED 标记）→ brw-takeover 反爬接管卡（warn 边 + 1.4s 脉冲点，「需手动完成验证」）。
  • 交互：模式切换不影响会话池（预热 / 空闲 60s 回收 / 上限 3 + 排队）；验证码特征 → 面板人工接管（复用 takeover 机制）；提取结果经 dual-LLM-lite 读取器结构化后带 provenance 包裹进上下文。
  • 动效链：模式切换 spring 200ms 滑块形变；运行态 1.4s 脉冲点（有限循环，fx-off 即停）；结果 UNTRUSTED 标记同计划卡三重编码。
  • 移植落点：39-search-panel.js（面板）+ 25-tool-exec.js（六工具分发 + isError 回传 + 校验反馈）；依赖后端 browser_* 六工具（M3 Win / M4 Mac / M5 工具面），详见第 6 章 B 类。
打开原型：浏览器驱动面板 design/v19/prototypes/browser-driver-panel.html

3.4 审批预算指示器 M2.4 / M2.5 · 26-guard.js 改 · R27

把「确认疲劳」变成可见数字：会话级审批计数内嵌授权条，超限不再续弹窗，而是升级为任务授权邀请。

  • 信息架构：授权条内嵌 grant-budget mono「审批 3/5」+ 5 格 dot；超限态 grant-budget.over 转 err「已达上限，需显式批准」；一键收回钮（grant-revoke，hover 品牌蓝 glow，禁扩散）；L0 禁快捷确认。
  • 交互：计数随 guard 判定链实时更新；超限 → 升级为任务授权邀请（一次性授予范围授权）而非继续逐项弹窗；授权条常驻一键收回。
  • 动效链：收回钮 hover 品牌蓝 glow（glow 白名单两处之一）；超限转 err 微反馈；计数变化 mono tabular-nums 直切，无装饰动效。
  • 移植落点：26-guard.js（预算提示 + 高风险档差异化 + 授权条增强）；依赖后端 guard_approval_budget（M2.4）与 guard.json 纯增键 approval_budget。
打开原型：审批预算指示器 design/v19/prototypes/grant-budget.html

3.5 macOS 适配层 M6.10-6.12 · 69-platform.js 新 · 双端一套令牌

08

注意事项与风险

移植与联调阶段的四条硬注意事项 + 两条对齐备忘。均来自彩格调方案 §4 风险项与评审移植提示。

1 · 双端 backdrop-filter 差异

WebView2（Chromium）与 WKWebView 的 backdrop-filter / overlay 滚动条表现不一致——mac 端玻璃拟态需双端实测矩阵。备选：mac 下提升 --glass-bg 不透明度补偿。本报告的玻璃效果在无 backdrop-filter 的环境自动回退 --glass-fallback 实色（prefers-reduced-transparency 亦走该回退）。

2 · mac 字体注入时序

SF 字体栈须早于首屏渲染注入——boot 前由 69-platform.js 设 body[data-platform="mac"] 根类，避免首屏字体闪烁（FOUT）与回流。

3 · 哈希链显示纪律

审计哈希链只显示首 8 位 + 省略号，禁长串全文（信息密度纪律）；断链一律转 err 态呈现，不静默。

4 · 演示 dwell 常量不移植

原型中的 stepDwell 900 / autoDwell 3000 / restoreDwell 1200 / primDwell 650 为原型演示专用节奏常量，不进产品代码、不进 MOTION；3s 自动批准徽标淡出是方案规格值需保留。演示对象（DEMO）与动效令牌（MOTION）是两套东西。

对齐备忘（2 条）

  • .plan-badge 过渡增补：模板现行 transition 仅 background-color / color；移植时纯增 opacity 项（见 7.3）。
  • 评审台宽度值：原型 --content-w:1080px 为评审台加宽值（便于并排双形态展示），产品值以 v4 令牌 920px 为准；本报告即按 920px 排布。
