# Harbor Agent 自主能力深化 · 调研与设计

**日期**：2026-10-20
**类型**：调研报告 + 功能设计（「解放用户双手」专项）
**基线**：v1.7.0（701 passed）+ v1.8.0 方案（浏览器搜索/软件调用/本地协同）
**状态**：v1.0（待产品负责人审定；§9 三个待确认问题需裁决）

---

## 📌 TL;DR

- **核心命题**：Harbor 的 Agent 今天「不敢放手」——每次破坏性操作都确认、任务无计划无追踪、出错无回滚。行业答案已经清晰：**权限阶梯（supervision dial）+ 计划-执行分离 + 检查点回滚 + 批量澄清**四件套；且行业数据表明**逐项确认大多是「监督剧场」**（用户约 93% 的批准是不读内容直接点）。
- **设计立场**（与「信任版」定位不自相矛盾）：自主不是赠品是**赚来的**——「严格起步、按证据放宽」（Safeguard 原则）；每一次放宽都可审计、可一键收回；高风险动作（工作区外删除/提权/凭证外传）**永远确认，任何模式不豁免**。
- **交付物建议**：四件套约 14.5 人日。建议编排为 **v1.8.0 带「任务授权 L2」（3 人日，guard 小扩展）**，**v1.9.0「放手版」带 Plan-Act + 批量澄清 + 检查点**（11.5 人日）；L3 智能自动（分类器）列为 v1.9.1 观察项。
- **与 v1.8 的关系**：四件套与浏览器搜索/软件调用/本地协同**正交**（一个放权、一个扩能力）；结果自验框架（v1.8 V1）是四件套的共同基座，不重复建设。

## 🎯 核心结论卡片

| 项目 | 内容 |
|------|------|
| 行业基准 | Claude Code 六档权限模式（default→acceptEdits→plan→auto→dontAsk→bypass）；auto 档用**后台安全分类器**替代人工批准，拦阻回传原因让 Agent 换路；Cline「人审产物不人审策略」+ 检查点随时回滚；Cursor plan 模式先澄清先出方案 |

## 1. 外部调研（2026-10-20，5 源交叉）

### 1.1 行业模式盘点

| 产品 | 自主模式 | 关键机制 |
|---|---|---|
| **Claude Code**（v2.1.83） | 六档权限：default → acceptEdits → plan → auto → dontAsk → bypassPermissions | auto 档=**后台安全分类器**（两阶段：快筛+深查）替代人工批准；不安全动作直接拦+回传原因，Agent 换路径；连续 3 次/累计 20 次拦阻 → 退回逐项询问；**永久删除关键路径永不自动批**；auto 模式因多跑分类器更耗额度 |
| **Cline** | Plan/Act 双模 + auto-approve 可选 | 哲学=「人审产物不人审策略」：默认每个编辑/命令需批准，但所有变更**检查点化**，可随时整体回滚；IDE 内 diff 呈现，可审可改 |
| **Cursor** | plan / agent / ask 三模 | plan 模式**先问澄清性问题**再出方案，批准后才执行；检查点可回滚到任意早先状态；CLI 同款模式 + 规则系统（.cursor/rules） |
| **Windsurf Cascade** | 偏 auto | 多步工作流最小打断执行 |
| **Devin 等后台平台** | dontAsk 端 | 委托任务→完成看 PR；人彻底出循环 |

### 1.2 两个改变设计的数据/原则

- **93% 橡皮图章问题**（The Stack Underflow）：若用户约 93% 的批准是不读直接点，逐项确认就不是监督而是剧场——人已在环外，UI 假装还在。Claude 的应对不是「少问」而是「换问的方式」：分类器审动作、拦阻回传原因。**Harbor 的 always 档同病**：删除确认框用户大概率也直接点。
- **Safeguard 放权原则**：① 严格起步、按证据放宽——把「反复批准的命令」升级为**窄白名单规则**，而不是把整个会话切到松模式；② 窄允许规则 > 松模式（其余仍拦）；③ deny 规则在所有模式生效（含 bypass）；④ 减少提示时必须配 OS 级边界（沙箱）——**Harbor 有 Job Object 沙箱，这是放权的独特底气**。

## 2. Harbor 现状与差距（代码库实测）

| 维度 | Harbor 现状 | 差距 |
|---|---|---|
| 权限粒度 | per-op 三档（always/session/off）+ confirm-token + 进程内/持久信任（guard.json trustedOps）+ 保护名单 | 无**任务级授权**（一次授权一类操作整任务有效）、无**白名单规则**（反复批准的动作升级自动）、无**范围约束**（工作区内/外分级） |
| 任务结构 | 回合制反应循环；R4 有 15 步无进展熔断 + 轮次上限 | 无 upfront 计划、无 todo 追踪、无执行偏差检测、无重规划 |
| 澄清交互 | Agent 文字提问，一次一个，用户答完继续 | 无结构化批量澄清（信息不足时合并一次问完） |
| 回滚 | 无。压缩有备份（50 条上限）但那是上下文压缩不是工作区回滚 | 无工作区快照/检查点/一键回滚（Cline/Cursor 的标配安全网） |
| 记忆 | `append_memory` 单向写入，无检索无偏好学习 | 跨会话记忆不可用（Agent 每天重新认识用户） |
| 放权安全基座 | **Job Object 沙箱已交付**（v1.6）+ 全量审计 + 熔断 | 基座行业领先——放权时「OS 级边界」这条 Safeguard 硬要求 Harbor 已满足 |

**结论**：Harbor 缺的不是「敢不敢放」的胆子，是放权的**工程结构**（阶梯、计划、检查点、澄清协议）。且放权时沙箱基座比 Cline/Cursor（依赖分类器+diff）更硬。

## 3. 设计 A · 自主权限阶梯（L0-L4）

### 3.1 阶梯定义

```
最监督 ←──────────────────────────────────────────────→ 最放手
  L0          L1            L2            L3            L4
逐项确认    会话信任      任务授权      智能自动      委托策略
(现 always) (现 session)  (新)          (新·v1.9.1)  (新)
```

| 级别 | 语义 | 适用 | Harbor 落地 |
|---|---|---|---|
| **L0 逐项确认** | 每个敏感操作弹窗 | 陌生代码库/高危任务 | 现 always 档，不变 |
| **L1 会话信任 + 范围自动** | 确认过的不再问；**工作区内的文件编辑/非破坏命令自动**，越界即问 | 日常迭代 | session 档 + 新增「工作区范围自动」规则（guard_service 加 scope 判定） |
| **L2 任务授权** | 任务开始用户一次性授权：「本任务内，工作区内文件写入 + 命令执行自动，破坏性操作（删/杀/剪贴板写/越界）除外」；带 TTL（默认 2h）+ 随时「收回授权」按钮 | 长任务/批量重构 | 新 `task_grant` 状态（guard_service 进程内 + 面板常驻指示灯） |
| **L3 智能自动** | 后台分类器（规则引擎 + 本地模型二级判定，复用 v1.8 H 组）审每个动作：低风险放行/高风险拦截回传原因；连续 3 次拦截退回 L1 | 重复性劳作 | 规则先行（路径范围+动词黑白名单+数据外传特征），本地模型判模糊 case；**任何模式不豁免的硬核清单除外** |
| **L4 委托策略** | 用户预授权白名单（「git commit 类永远自动」），仅白名单动作自动，其余维持 L1；支持随时查看/删规则 | CI 式无人值守 | `guard.json` 新增 `allow_rules`（op+detail 模式匹配），Safeguard 窄规则模式 |

### 3.2 永不豁免清单（deny rules，所有级别生效）

1. 删除/写入**工作区外**路径（保护名单之外的第二道闸）
2. 提权执行（run_admin_command 永远人审——沙箱也无法收编提权进程，v1.6 已定性）
3. 凭证类外传（剪贴板写入含 Key 特征的内容 + 网络外传——后者借 v1.8 搜索通道审计）
4. 永久删除关键路径（系统目录/用户文档根）
5. guard off 档的手动关闭（off 只能由用户在设置显式关闭，Agent 无权）

### 3.3 与既有护栏的关系（不改语义只加维度）

现有三档是 **op 维度**，本方案加 **任务维度（L2 grant）与规则维度（L4 allow_rules）**——判定顺序：`deny 清单 → allow_rules → task_grant → op 档位 → 确认弹窗`。confirm-token/审计/武装标志全部沿用。

## 4. 设计 B · Plan-Act 计划执行模式

### 4.1 流程

```
用户发送任务
  └─> 【Plan 阶段】本地模型（v1.8 H 组）理解意图 → 生成计划：
       · 步骤清单（可编辑）+ 涉及文件/命令预声明 + 风险标注（哪些步骤会触发 L0/L2）
       · 信息不足 → C 批量澄清（一次问完）再出计划
       └─> 用户：批准 / 编辑后批准 / 拒绝对话式修改
  └─> 【Act 阶段】按计划执行：
       · todo 状态机（pending/doing/done/blocked/skipped）实时可见
       · 每步完成自标状态；偏差检测：实际调用与计划声明不符 → 轻微偏差自适应继续，
         重大偏差（计划外删/越界/提权）→ 暂停回问
       · 上下文压缩/归档不丢计划（计划进系统提示常驻）
  └─> 【交付】V1 校验框架（v1.8）跑结果自验 → 交付摘要：改了什么/验证结果/未决事项
```

### 4.2 关键点

- 计划即**契约**：Act 阶段的越界检测以计划为基准（计划外操作=重大偏差）
- 计划可编辑：用户批准前可增删步骤、改风险标注
- 失败重规划：步骤 blocked 时 Agent 可提议修订计划（用户确认或 L2 授权内自适应）
- UI：对话流顶部计划卡（步骤 checklist）+ 偏差暂停条

## 5. 设计 C · 批量澄清协议

- **触发**：Plan 阶段检测到信息不足（多选一缺失/路径不明/范围不清）
- **形态**：`clarify` 伪工具——Agent 一次提交问题清单（≤5 问，每题：问题 + 选项 + 默认值），UI 渲染为单张表单，用户一次答完（可用默认值一键确认）
- **原则**：信息不足攒着一次问，禁止执行中挤牙膏式单问（单问仅限「不答就无法安全继续」的阻断级）

## 6. 设计 D · 检查点与回滚

| 层 | 机制 | 说明 |
|---|---|---|
| git 仓库 | 任务开始 `git stash create`/记录 HEAD → 回滚 = 恢复该 ref | 不碰用户分支状态，只做恢复锚点 |
| 非 git 工作区 | 任务涉及文件快照（复制到 `~/.glm-chat/checkpoints/<task_id>/`，上限 200MB/500 文件，超限降级为「仅记录 diff 清单」） | 只快照**计划声明涉及**的文件，不全工作区拷贝 |
| 回滚入口 | 计划卡「回滚到此任务前」按钮 + 完成摘要里的回滚链接 | 回滚前展示将恢复的文件清单（二次确认） |
| 与压缩备份的关系 | 压缩备份（50 条）管上下文，检查点管**磁盘**——两层互不替代 | — |

## 9. 风险矩阵

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| R1 | **放权与「信任版」定位冲突**（用户觉得产品背叛初心） | 高 | 设计三栓：硬核清单永不豁免 + 全量审计 + 一键收回；默认仍 L0/L1，放权必须用户显式开启；文档明示「自主是赚来的」 |
| R2 | L2 任务授权被滥用（授权内做计划外的事） | 高 | 授权=提权不是免检：deny 清单 + 沙箱仍在；偏差检测（B2）盯着；授权 TTL + 收回按钮常驻 |
| R3 | 白名单规则过宽（用户把危险命令加进白名单） | 中 | 规则创建时风险提示（动词命中 WRITE_VERBS/危险特征时警告）；deny 清单覆盖的规则无效；规则列表可审计 |
| R4 | 检查点磁盘膨胀 | 中 | 仅快照计划涉及文件 + 200MB/500 文件上限 + 超限降级 + 完成后保留策略（默认保留至下个任务，可配置） |
| R5 | 计划质量差导致 Act 反复偏差 | 中 | 计划可编辑；重大偏差才停；本地模型生成 + 模板约束；连续 2 次重大偏差 → 退回 L0 逐项 |
| R6 | L3 分类器误判（放过高风险） | 高（v1.9.1） | 规则引擎优先（确定性判定），本地模型只判模糊 case；deny 清单先于分类器；连续拦截退回；灰度：L3 默认关，用户显式开 |
| R7 | 批量澄清问错问题（该问的不问） | 低 | 澄清仅在 Plan 阶段；每题带默认值；用户可「直接按默认继续」 |

## 10. Non-goals

1. **不做全自动无人值守版本**（L4 之上的 bypass）——无人值守需容器级隔离，超出桌面产品边界；行业共识（Safeguard：bypass 仅限一次性容器）。
2. **不做多 Agent 并行协作**——v1.9+ 观察项，先做好单 Agent 放手。
3. **不改 guard 三档既有语义**——只加任务/规则维度，既有测试与用户认知零迁移成本。
4. **不让 Agent 自行放宽自己的权限**——任何放权动作必须经用户显式操作（UI 或规则确认）。
5. **不做跨设备策略同步**（WebDAV 数据主权是另一条线）。
