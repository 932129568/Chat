# GLM-Chat 竞品分析报告（2026-10）

**日期**：2026-10-15
**类型**：竞品分析
**参与成员**：方向明（主理人/汇编）、竞析（竞品分析师）、数析（数据分析师）、瑞思（用户研究员）
**分析对象**：GLM-Chat v1.2（Windows 桌面 AI Agent 客户端，BYOK + 本地 + 直接执行）

---

## 📌 TL;DR（执行摘要）

- **核心结论**：「BYOK 自带 Key + 完全本地 + 直接 Agent 执行（命令+文件）」的交集在桌面端**无人占据**——竞品要么执行弱（Cherry Studio/Chatbox/NextChat）、要么生态封闭（Claude Desktop）、要么绑 IDE（Cline）、要么按 token 抽成（Cursor）。这是 GLM-Chat 的结构性卡位空白。
- **关键决策**：v1.2 只承接三条差异化机会（透明可审计 Agent 执行 / 极致成本工程 / 单文件分发靠自动更新保鲜），隐私数据主权是架构红利只做不讲，Windows 深度集成维持现状；多模型是防御性对冲而非能力扩张。
- **最大威胁**：Cherry Studio 的超强执行力（682 open issues、50+ 服务商）+ Claude Code 全平台挤压 + MCP 正成事实标准。
- **下一步**：社区生态位（开 issue 区/讨论区）立即启动，零开发成本；按季度用本报告重估 P2 排序。

## 3. 市场数据 & 趋势（来源：数析）

- **市场规模**：AI 编程助手市场 CAGR 26–46%（多机构口径），2025 年中国 AI 编程助手市场约 ¥42–49 亿——高增长赛道，但国内付费空间受大厂免费策略（通义灵码/Trae/CodeBuddy）压制。
- **定价基准**：GLM-5.3 输入 ¥0.8/M、输出 ¥2.8/M、缓存命中输入 ¥0.16/M（4 小时滚动窗口）；GLM Coding Plan 轻量 ¥20/月、Pro ¥118、Max ¥538、Ultra ¥1078，仅限官方 20+ 工具，第三方接入报 1113。
- **成本账**：Agent 任务 ≈ 10.7 万 token ≈ ¥1.2/任务；轻量任务 ≈ ¥0.3/任务；缓存命中可省约 20% 总成本；GLM-6/6V 视觉单价为文本 5–10 倍。
- **趋势判断**：① MCP 正成工具接入事实标准；② 权限透明已成行业标配预期（Claude Code 教育了市场）；③ 大厂免费策略压制付费，但打不到「数据主权+隐私」利基；④ 用户成本焦虑是结构性的（套餐政策收紧 + 按量计费不可预测）。

## 4. 用户感知（来源：瑞思）

- **选品标准排序**（瑞思研究）：**权限可控是第一选购标准**（超过模型能力、超过价格），成本透明第二。用户要的是「AI 正在对我电脑做什么」的确定性与 token 花去哪的掌控感。
- **对竞品的用户感知**：Cline——执行最强但「Agent 烧钱」恐惧集中地（社区账单 $60–90/月、循环任务 $80–250、过夜 $50–500）；Cherry Studio——功能全但配置复杂，面向「折腾型」用户；Chatbox——轻量可信但无执行能力；Cursor——体验好但按 token 抽成且资源重。
- **对本品的启示**：用户不要「功能最多的」，要「敢放手用的」。本品已有的预算/压缩/截图去重是品类内最强留存理由，但只防「正常路径」，不防「Agent 犯病」——v1.2 的熔断与硬停正是补这块。
- **反共识警告**：护栏缺位时加多模态会放大 Agent 失控问题——信任优先于能力扩张。

## 6. 差异化机会（来源：竞析，含 v1.2 承接判断）

| # | 机会 | 为什么是我们 | v1.2 承接判断 |
|---|------|--------------|----------------|
| ① | **透明可审计的 Agent 执行** | 执行深度已是本品既有资产，把「黑盒执行」升级为「玻璃房执行」是行业空白；直接回应信任赤字（瑞思） | ✅ 全部 P0 服务于此（护栏/通知/熔断/审计） |
| ② | **极致成本工程** | 品类唯一把「省钱」当产品叙事；已有预算/压缩/去重资产；BYOK 用户成本焦虑结构性（数析） | ✅ 熔断硬停 + 成本透明化（R4/R5） |
| ③ | **隐私与数据主权** | API Key 自持 + 敏感数据不出网；大厂免费策略打不到的利基 | ⬜ 架构红利，v1.2 只做不讲（遥测维持默认关即体现） |
| ④ | **单文件分发 + 零安装** | <2MB onefile 即开即用，竞品全需安装包 | ✅ 自动更新补保鲜短板（R1） |
| ⑤ | **Windows 深度集成** | Cursor/Cline 留空的本地系统集成面 | ⬜ 维持现状，不作为 v1.2 主题 |

**多模型定位说明**：多模型不是差异化机会，是对「仅 GLM」这一 SWOT 短板的**防御性对冲**（1113 服务商事件 + Cherry Studio 50+ 服务商的执行力对比）。竞析判断「竞品已 50+ 服务商，跟随策略成立，但保留最小对冲」——v1.2 以 OpenAI 兼容端点 + 首家 DeepSeek 接入完成最小对冲（R6），是唯一允许降级到 v1.3 的需求。

## 7. 行动建议

1. **立刻启动（零开发成本）**：开 GitHub issue 区/讨论区、响应 issue——竞析指出的社区生态位缺位，纯运营动作，需主理人每周固定投入。
2. **v1.2 全力做信任基建**（详见 PRD）：把「透明可审计执行 + 成本工程 + 自动更新」三条机会落地，不做能力扩张。
3. **持续跟踪两项外部变量**：① GLM Coding Plan 对第三方的开放政策（若破例，成本叙事升级为王炸）；② MCP 协议稳定性（v1.3+ 评估接入，但必须后置于护栏）。
4. **严守四大约束**（竞析）：服务商依赖 → 多模型最小对冲；执行能力-资源约束悖论 → 不做浏览器 Agent、严守工作量范围；跨平台与单文件分发张力 → macOS 不早于 v2.0；社区缺位 → 设为持续运营项。
5. **每季度末重估 P2 排序**：用竞析（竞品动态）+ 数析（本地指标）+ 瑞思（用户反馈）三方输入滚动修正路线图。
