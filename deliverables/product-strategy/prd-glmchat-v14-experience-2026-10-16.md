## 📌 TL;DR（执行摘要）

- **核心目标**：v1.4 不做大功能，做**体验补完 + 效率量化**——修四个日常主循环里实测出来的 UX 痛点，落地一套「缓存优先」的省 token 组合拳，只带两个小功能（会话导出 / MCP 超时可配）。总估约 13.5 人日，单批发布。
- **量化主轴**：同等标准任务链（3 条基准）总 token 消耗 **-25%**（硬门）/ cache 命中率 **≥60%**（硬门）/ -30%（stretch）——v1.2 以来第一次给「省」设可证伪的数字。

- **下一步**：产品负责人审定本方案并裁决第 7 节三个待确认问题 → W0 冻结 → W1-W3 开发 → 基准复跑 → 发布 v1.4.0 → 发布后一轮代码审查（沿用 1.3.x「功能→审查→硬化」模式）。

## 1. 版本目标

v1.3.x 把「信任」和「生态」补完了，v1.4 补**日常体验**和**效率证据**。三个目标：

- **G1 日常摩擦清零（主题）**：把每日主循环（给任务 → 看 Agent 干活 → 确认危险操作 → 查花费 → 找旧会话）里实测存在的四类摩擦修掉——静默压缩造成的「AI 忘了」困惑、确认弹窗疲劳、会话无检索、设置面板大海捞针。
- **G2 省 token 可证伪（量化主轴）**：省 token 机制从 v1.0 起就有（A2 瘦身 / 冻结层 / 自动压缩 / 截图去重 / 智能档），但**从来没有被量化验证过**。v1.4 第一次建立基准协议：3 条标准任务链前后对比，总 token -25% 硬门、cache 命中率 ≥60% 硬门。核心策略是缓存优先——GLM 缓存命中输入价差 5 倍（¥0.16/M vs ¥0.8/M），让前缀稳定比激进压缩更省钱。
- **G3 功能克制**：只带两个零攻击面增量的小功能（会话导出、MCP 超时可配）。1.3.x 刚用 MCP 扩了执行面并修了两轮硬化（78+63 项），本版不再扩协议面。

**衡量方式**（零成本本地指标，数析口径扩展）：总 token（输入/输出细分）、cache 命中率、请求轮次、压缩触发次数、单任务花费；新增「持久信任启用数」「会话搜索使用率」「导出使用率」三个行为指标。全部本地记录，不引入遥测（既有 Non-goal 不动）。

## 2. 用户故事

- **US-1（画像 A，主力）**：作为按量付费的开发者，我希望在历史被自动瘦身/压缩时**能看到哪条内容被摘要了、省了多少 token、原文还能找回**，以便不再怀疑「AI 是不是忘了 earlier 的要求」而被迫重开任务。
- **US-2（画像 A）**：作为每天确认几十次删除/剪贴板操作的用户，我希望对确实安全的操作能选「永久信任」（重启后仍生效、随时可重置），以便确认弹窗不再打断工作流。
- **US-3（画像 A/B）**：作为会话越攒越多的用户，我希望跨会话关键词搜索并跳到命中位置，以便三天前那个改过的文件方案不用翻聊天记录翻十分钟。
- **US-4（全体）**：作为想把 Agent 工作实录分享给同事/贴 issue 的用户，我希望一键导出会话为 Markdown，以便不截图不手抄。

| Stretch | 总 token -30% |
| 环境限制（如实） | 本开发环境无外网——基线采集与复跑需在目标机执行；本环境只能保证测试层（单测/契约/构建）全绿 + 记录协议与模板就绪 |
| 不达门处理 | 若复跑只到 -20%：允许发布但需在交付报告写明差距归因（阈值保守 or 反噬），并把残留优化列入 v1.4.x；**不允许为凑数字牺牲质量**（如无脑砍 keepTail 导致 Agent 重读） |

### 4.4 主要风险与对冲

| 风险 | 对冲 |
|---|---|
| TOK-3 收紧阈值 → Agent 丢失中间工具结果 → 重读文件反噬（输入省了轮次多了） | 与 UX-1 透明化同批上线（用户可见可恢复）；基准链②③实测轮次不升才收口 |
| TOK-4 路由增强漏路由 → LLM 调用未下发工具失败 → 多轮补救 | 路由集含「最近调用域 ∪ 保底域」；单测覆盖三类输入边界；保留「全量下发」降级开关（设置里可关路由裁剪） |
| UX-2 持久信任 → 用户忘切 → 危险操作无确认执行 | 首次永久信任强制风险文案；设置里信任清单可见 + 一键重置；审计日志照记（decision=trusted-persistent） |
| UX-1 备份机制 → sessions 落盘体积膨胀 | 备份仅存被替换消息原文、上限 50 条、超限标记不可恢复；备份随新压缩覆盖（单份） |
| F2 超时上限放到 300s → 卡死服务器拖死会话 | 前端桥接 timeoutMs 同步放大但保留总上限；R4 熔断不受影响（按签名计数） |

## 6. Non-goals（明确不做）

1. **不做 WebDAV/云同步/数据主权**：推迟 v1.5 独立 PRD（Grill 分支 1 裁决；与「完全本地」定位的张力需专门设计冲突合并 UX）。

5. **不为凑量化数字牺牲质量**：如无脑砍 keepTail/关路由导致 Agent 重读或漏工具的「假省」——验收以基准链轮次与质量为并列硬门。

## ⚠️ 假设

- 工作量基于 v1.3.x 模块化结构与 347 测试网的既有 velocity；UX-1 备份机制若在 session 存储上遇到意外复杂度（如 localStorage 配额），最坏 +1 人日，缓冲在 T3。
- 「缓存命中率」假设 GLM 端点持续返回可用的缓存计价字段（v1.2 R5 三价计算已依赖，风险已知可控）；自定义端点无缓存计价时双条件退化为「仅 token 阈值」（行为不回退于 v1.3.2）。
- 基准任务链的 -25% 目标假设任务链设计能代表真实用法；若实测发现固定开销（工具 schema/系统提示）占比远高于预期，优化重心应在 T4 路由（已含）而非继续砍历史（Non-goal 5 防伪）。
- 会话搜索性能假设 sessions 量级在数百会话以内（localStorage 全量遍历可接受）；若用户会话达数千，需加分词/索引，列为 v1.4.x。
