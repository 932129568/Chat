## 1. 产品目标

v1.2 不做能力扩张，做**信任补完**。三个目标正交，分别对应"敢不敢用、敢不敢放手、能不能一直用"：

- **G1 信任显性化**：Agent 每一次破坏性操作、每一分钱花费都"看得见、拦得住、说得清"。把权限可控从用户的选购标准变成产品默认体验，消灭安全等级不一致（delete/kill/剪贴板/截屏无确认）这类会被重度用户一眼识破的破绽。（来源：瑞思发现③）
- **G2 成本防御闭环**：从"事后看账单"升级为"事前预估、事中熔断、事后归因"。本产品已有的预算/压缩/去重是品类内最强留存理由（瑞思发现②），v1.2 把它从隐藏功能变成产品叙事主线。（来源：瑞思②、数析 P0-b）
- **G3 分发可持续**：补齐自动更新这块隐形天花板，让单文件分发即开即用的优势不被"用户停留在旧版本"抵消。（来源：瑞思发现④、竞析差异化机会④）

**衡量方式**（零成本本地指标，来源：数析）：预算触达率、权限档位分布、命令成功率、写后纠正率、截屏频率、压缩节省 token、缓存命中率、周活跃天数。v1.2 上线后以这些指标做验收复盘，不引入商业报告数据（数析决策建议）。

## 2. 用户故事

- **US-1（画像 A，主力）**：作为按量付费的个人开发者，我希望 Agent 删除文件/结束进程/读写剪贴板/截屏前必须经我确认（或命中我配置的保护名单），以便我授权 Agent 自主干活时不再提心吊胆。
- **US-2（画像 A）**：作为 token 焦虑用户，我希望发送任务前看到预估花费、会话烧到预算时自动暂停而不是继续扣钱，以便放手让 Agent 跑长任务。
- **US-3（画像 D，假设）**：作为重度 Agent 用户，我希望会话陷入循环（同一工具同一参数反复调用）时自动熔断并告诉我原因，而不是一觉醒来发现过夜任务烧掉几百块。
- **US-4（全体）**：作为老用户，我希望启动时自动检查新版本、一键下载更新并看到更新说明，不用手动去仓库查 release。
- **US-5（画像 B）**：作为想用 DeepSeek/Qwen 的开发者，我希望粘贴一个 OpenAI 兼容的 Base URL + Key 就能切换模型，以便在 GLM 服务波动时有退路。

## 3. 用户研究洞察（来源：瑞思）

**核心用户**：画像 A（BYOK 按量付费、对 token 成本高度焦虑的 Windows 个人开发者）为绝对主力；B（跨编辑器自主控开发者）、C（隐私优先谨慎用户）为次要人群；D（重度 Agent 协作者）为假设人群，v1.2 按 D 的需求设计熔断但不按 D 做能力扩张。

**五大发现中对 v1.2 的直接约束**：
1. GLM Coding Plan 仅限官方指定工具、自建调用报 1113 余额不足——用户成本敏感是**结构性**的，省钱必须是产品叙事而非功能点。
2. 「Agent 烧钱」是品类最大恐惧（Cline 用户月账单 $60–90、循环任务 $80–250、过夜 $50–500）——本产品已有的预算/压缩/截图去重是最强留存理由，v1.2 目标是把留存理由**显性化**。
3. 权限可控是第一选购标准，但 delete/kill/剪贴板/截屏面上无确认——**安全等级不一致比没有安全更糟**，会被重度用户识破并否定整个权限体系。
4. 无自动更新是隐形天花板，同类项目高频抱怨。
5. 多模型/跨平台已是社区预期基线——v1.2 以 OpenAI 兼容端点满足多模型一项，跨平台明确不做（见 Non-goals）。

**反共识警告（采纳）**：护栏缺位时加多模态会放大 Agent 失控问题。v1.2 拒绝一切多模态/视觉模型扩展（含 GLM-6V），信任优先于能力扩张。

## 4. 竞品对比（来源：竞析）

| 产品 | 分发形态 | 模型来源 | Agent 执行深度 | 权限/确认机制 | 成本工程 | 自动更新 |
|---|---|---|---|---|---|---|
| **GLM-Chat（本品）** | 单文件 exe，零安装 | BYOK（GLM） | 深（命令+文件+剪贴板+进程+截屏） | 三档权限，但确认面不全 | **最强**（预算/压缩/去重） | **无** |
| Cherry Studio | 桌面安装 | 50+ 服务商+MCP | 弱（无命令/文件执行） | 无 | 弱 | 有 |
| Chatbox | 桌面+移动端 | 多服务商 | 弱 | 无 | 弱 | 有 |
| Claude Desktop | 桌面安装 | 仅 Claude | 强（MCP 鼻祖） | 完整 | 无（订阅制） | 有 |
| Cline | VS Code 插件 | 多服务商 | 最强 | 有人审节点 | 无（成本失控明显） | 有 |
| Cursor | 桌面安装 | 自有多模型 | 强 | 有 | 弱（按 token 抽成） | 有 |
| 通义灵码/Trae | IDE 插件 | 大厂自有 | 全链路 | 有 | 免费策略 | 有 |

**卡位结论**：「BYOK 自带 Key + 完全本地 + 直接 Agent 执行」的交集在桌面端无人占据——竞品要么执行弱（Cherry/Chatbox）、要么生态封闭（Claude Desktop）、要么绑 IDE（Cline）、要么抽成（Cursor）。

**对 v1.2 的取舍**：竞析五条差异化机会中，v1.2 只承接三条——① 透明可审计的 Agent 执行（行业空白，直接回应信任赤字，对应 R2/R3/R4）；② 极致成本工程（对应 R4/R5）；④ 单文件分发靠自动更新保鲜（对应 R1）。③ 隐私数据主权是现有架构红利，v1.2 只做宣传不讲故事；⑤ Windows 深度集成维持现状。**多模型（R6）是为弥补"仅 GLM"这一 SWOT 短板、对冲服务商依赖风险（1113 事件）的防御性投入，不是能力扩张。**

## 5. 数据依据（来源：数析）

- **定价基准**：GLM-5.3 输入 ¥0.8/M、输出 ¥2.8/M、缓存命中输入 ¥0.16/M（4 小时滚动窗口）。
- **成本账**：Agent 任务 ≈ 10.7 万 token ≈ **¥1.2/任务**；轻量任务（10 次工具调用+2 张截图）≈ ¥0.3/任务；缓存命中可省约 20% 总成本；GLM-6/6V 视觉单价为文本 5–10 倍。
- **套餐与 1113**：Coding Plan 轻量 ¥20/月、Pro ¥118、Max ¥538、Ultra ¥1078，仅限官方 20+ 工具，第三方接入报 1113。
- **本地指标体系**：14 个零成本指标已设计完毕（含预算触达率、缓存命中率、压缩节省 token 等），v1.2 成本透明化（R5）直接复用该指标体系作为数据源，不新增采集成本。
- **决策建议转化**：数析 P0-a「页面直接展示成本」→ 转化为 R5（登录态接入 Coding Plan 涉及账号体系，v1.2 不做，见 Non-goals）；P0-b「预算触达行为显性化+会话级熔断」→ 原样转化为 R4；P1-a「先接 DeepSeek-V4.1-256K」→ 转化为 R6 的接入顺序。

## 6. 需求池

### P0（全部纳入，对应瑞思 P0 四项）

**分组论证**：P0 是一个整体——R2/R3 建"操作信任"，R4 建"花费信任"，R1 保"版本信任"。四项缺一，G1/G2/G3 任一目标落空。

| 编号 | 需求 | 优先级 | 验收标准 | 估算工作量 |
|---|---|---|---|---|
| R1 | 自动更新（最小版）：启动时后台检查更新→有新版本时应用内提示→用户点击后下载（SHA256 校验）→重启替换→展示更新说明 | P0 | Given 客户端启动且存在更新版本，When 用户点击「更新」，Then 下载完成后提示重启且重启后版本号变化；Given 下载中断或校验失败，When 重试，Then 保留旧版本可用并给出明确错误状态；Given 无新版本，Then 静默无提示 | 7 人日（更新源客户端+下载校验 4、onefile 自替换脚本 1.5、UI 与更新说明 1.5） |
| R2 | 护栏拉齐+安全等级一致：delete/kill/剪贴板读写/截屏纳入确认框架（每次确认/保护名单/会话内不再提示三档可配）；RunDeduper 补接至 standard 命令路径并修复 `rem ` 前缀绕过 | P0 | Given Agent 调用 delete 且该操作未命中保护名单、When 执行前，Then 弹出确认展示完整路径与文件大小，用户拒绝则工具不执行且向 Agent 返回拒绝原因；Given 用户配置 `C:\Users\*\Documents\**` 进保护名单，When Agent 尝试删除该路径下文件，Then 直接阻断并向 Agent 说明；Given 同一会话内 Agent 连续发起 3 条相同命令（含 `rem ` 前缀变体），When 第 2 条发起时，Then 被 RunDeduper 拦截并要求用户确认 | 8 人日（确认矩阵框架 3、保护名单配置 1.5、RunDeduper 补接+绕过修复 2、测试 1.5） |
| R3 | 通知体系升级：alert/confirm 全面替换为应用内 toast/状态条（成功/警告/错误三态视觉分离）；修复 16 处静默吞错（错误至少可见于日志+toast） | P0 | Given 任意工具执行失败，When 结果返回，Then 界面出现错误 toast 且明细可展开，不再有静默失败；Given 连续多条通知，When 触发，Then toast 队列不重叠、可手动关闭；Given 破坏性确认场景，Then 走 R2 确认框架而非 toast | 5.5 人日（toast 组件 2、替换调用点 1.5、吞错修复 2） |
| R4 | 成本失控防御显性化：预算触达后硬停（停止发起新请求，语义见流程 7.2）+ 会话级循环/步数熔断（同工具同参数 3 次或连续 15 步无进展即暂停并询问用户） | P0 | Given 会话预算已用尽，When Agent 尝试发起下一次 API 调用，Then 调用被阻断、界面显示暂停状态与三个选项（提高预算/终止会话/只读模式继续）；Given Agent 循环调用同一工具同一参数，When 第 3 次发起，Then 自动暂停并高亮循环工具调用序列；Given 熔断触发，When 用户选择恢复，Then 从断点继续且不重复扣费 | 6 人日（硬停检查点 2、循环检测 2、熔断 UI 与恢复 1、测试 1） |

## 7. 关键流程

**7.1 破坏性操作确认流程（R2）**
```
Agent 发起工具调用（delete/kill/剪贴板写/截屏）
  └─> 查确认配置（每操作三档：每次确认 / 保护名单 / 会话内不再提示）
       ├─ 命中保护名单 ──> 直接阻断，向 Agent 返回「受保护路径/进程，已拒绝」
       ├─ 会话内已信任 ──> 放行，记录审计日志
       └─ 需确认 ──> 弹确认框（操作类型 / 完整路径或进程名 / 影响面）
            ├─ 用户拒绝 ──> 工具不执行，向 Agent 返回拒绝原因，Agent 自主调整方案
            └─ 用户同意 ──> 执行，结果入审计日志
```

**7.2 预算熔断流程（R4）**
```
每轮 API 调用前 & 每个工具调用后 → 检查点
  ├─ 预算未触达 & 无循环特征 → 放行
  ├─ 预算触达 ──> 硬停：不再发起新请求
  │     └─> 暂停态 UI：本会话已花费 ¥X / 预算 ¥Y
  │           ├─ 提高预算（输入新额度）→ 断点续跑
  │           ├─ 终止会话（保留上下文，可导出）
  │           └─ 只读模式继续（仅对话不执行工具）
  └─ 循环特征（同工具+同参数 ×3，或连续 15 步无状态推进）
        └─> 熔断暂停，高亮循环调用序列，用户选择：终止 / 手动指引后继续
```

**7.3 自动更新流程（R1）**
```
启动 → 后台异步请求更新源（GitHub Releases / 备用源）
  ├─ 无新版本 → 静默
  └─ 有新版本 → 状态栏轻提示「v1.2.1 可用」+ 更新说明入口
        └─> 用户点击「下载并安装」
              ├─ 后台下载 → SHA256 校验
              │     ├─ 失败 → 保留现版本，错误 toast，可重试
              │     └─ 成功 → 提示「重启完成更新」（保存会话草稿）
              └─> 退出时辅助脚本替换主程序 → 重启 → 展示新版本更新说明
```

## 8. Non-goals（明确不做）

1. **不做浏览器 Agent**：竞析已论证约束——不读屏幕+单文件分发做不了浏览器操作，且瑞思警告护栏缺位时扩展执行面会放大失控。截图能力维持工具调用辅助定位，不扩展为浏览器操控。
2. **v1.2 不做 macOS/跨平台**：竞析指出跨平台与单文件分发存在张力；瑞思列 P2。v1.2 后置到路线图，先验证 Windows 更新与多模型稳定再议。
3. **不做 MCP**：虽是事实标准（竞析 SWOT 威胁项），但 v1.2 信任优先，MCP 引入的外部工具面与护栏拉齐目标冲突，v1.3+ 评估。
4. **不做多模态/GLM-6V**：瑞思反共识警告——护栏缺位时加多模态放大失控；数析亦建议纯视觉用 GLM-6 而非 6V。v1.2 一律不碰。
5. **不做账号体系/登录态接入 Coding Plan/云同步**：数析 P0-a 的登录态方案涉及账号与合规成本，v1.2 仅做成本展示（R5），接入引导以文案+外链完成。
6. **不做插件市场/生态**：竞析明确本品社区生态位缺位是长期战，v1.2 不投入。
7. **不改动 50 个 js_api 契约**：v1.1 重构刚以契约差分测试稳定，v1.2 任何需求不得破坏契约（R6 验收标准已含此项）。
8. **不引入商业报告数据做决策**：全程用数析的 14 个本地指标。
