## 1. 当前指标表现（来源：数析）

**可观测基线（本地指标，14 项零成本）**：周活跃天数、人均会话数/时长、工具权限档位分布、写后纠正率、命令成功率、截屏频率与去重命中率、工具调用超时率、预算触达率、压缩节省 token、缓存命中率、token 消耗趋势、周 API 成本等。这些指标构成 v1.2 的验收复盘基线，全程不引入商业报告数据（数析决策建议）。

**数据缺口（如实说明）**：
- 无真实使用数据——本地应用无遥测，当前所有规模类判断（DAU、留存、转化率）均为**假设**，不能作为路线图承诺依据；可作方向性参考（瑞思画像结构、竞析社区热度、数析市场报告）。
- 无成本漏斗数据（发起→执行→成功→纠正）的实测分布，R4 熔断阈值默认值需上线后按本地指标校准。
- 无渠道数据（分发来源不可见），GitHub star/release 下载量只能代理观测。

**结论**：路线图排期以工作量与依赖为锚，不依赖上述缺失数据；数据缺口本身即 v1.3 遥测最小版的立项理由。

## 2. 用户反馈摘要（来源：瑞思）

- **需求节奏判断**：信任优先于能力扩张。P0（自动更新/护栏拉齐/通知升级/成本防御）是「敢不敢用」问题；多模型/跨平台/云同步是「好不好用」问题——顺序不能颠倒。
- **核心恐惧**：「Agent 烧钱」（Cline 用户月账单 $60–90、循环任务 $80–250、过夜 $50–500）与「Agent 失控」是品类两大采用障碍，直接对应 R4 与 R2。
- **反共识警告（已采纳为排序约束）**：护栏缺位时加多模态会放大 Agent 失控问题——多模态/GLM-6V 一律不进 v1.2，且进 v2.0 前需过「护栏成熟度」前置门。
- **社区预期基线**：多模型/跨平台已是同类项目用户的默认预期——v1.2 以 R6 满足多模型一项，跨平台明确后置（v2.0）。

## 3. 竞品动态（来源：竞析）

三项时间窗口压力，直接决定「什么必须快、什么可以慢」：

1. **Cherry Studio 上攻（快）**：682 open issues、50+ 服务商、MCP/WebDAV/知识库全家桶，执行力最强。若其补 Agent 执行能力，本品卡位削弱。**应对：信任基建速度就是防守速度，v1.2 不可延期；社区运营立即启动。**
2. **Claude Code 挤压（中）**：Claude Code 全平台 + MCP 生态持续吸走高端用户。**应对：守住「BYOK + 本地 + 数据主权」利基，不与其拼生态，把成本透明做到极致。**
3. **MCP 标准化窗口（慢）**：MCP 正成工具接入事实标准，缺席有边缘化风险，但协议仍在演进。**应对：v1.3 评估接入，且必须后置于护栏（外部工具面必须先进确认矩阵）；每季度重估。**
4. **补充变量**：WorkBuddy（腾讯）等大厂桌面 Agent 直接对位且支持 GLM——需纳入季度竞品重估；GLM Coding Plan 第三方开放政策（1113 收紧先例）若变化，立即重估 R5/R6 范围。

### 4.3 发布策略（路径结论）

- **三批而非一批**：安全批（R2/R3/R4）是其他一切的地基，先发可让信任基建最早到达用户；开放批（R6）若出问题不影响已发布的信任资产。
- **每批 DoD（硬门槛）**：① pytest 契约差分测试通过（50 个 js_api 零变更）；② 该批需求验收标准逐条走查通过；③ 手动冒烟：确认/熔断/更新三流程；④ 本地指标基线记录归档。
- **降级规则**：若时间线告急，仅 R6（多模型）可整体降级到 v1.3；P0 四项（R1–R4）不可裁剪。
- **版本内顺序**：R2（护栏）必须先于 R3（通知）就绪最小可用版——确认框是通知体系的第一个消费者。

## 5. 利益相关者沟通要点（按受众，来源：路径）

### 5.1 高管 / 产品负责人版（一页）

- **一句话**：v1.2 花约 45 人日（单人 9 周）把「用户敢不敢让 AI 碰自己电脑」这个品类最大采用障碍变成我们的卖点，同时补齐自动更新这块分发短板。
- **要什么**：确认 6 个待确认问题（PRD §10）；接受「安全批先手动分发一次」；授权社区运营每周 2–4h 持续投入。
- **风险提示**：R6 多模型是唯一可降级项；若 GLM Coding Plan 政策突变，R5/R6 范围需重估（已有周跟踪机制）。
- **回报**：卡位空白窗口期（竞析：BYOK+本地+执行桌面端无人占据）+ 成本叙事品类领先 + 版本分发可持续。

### 5.2 工程版

- **红线**：50 个 js_api 契约零变更（pytest 契约差分是发布门）；写操作串行规则与硬规则文案不得破坏。
- **关键技术决策**：① 「工具调用前检查」统一挂点是 R2/R4/R5 的共同基础，最先落地；② RunDeduper 补接 standard 路径并修 `rem ` 前缀绕过（安全修复先行）；③ provider 抽象保持 GLM 默认、计费按 usage 字段适配；④ onefile 自替换用辅助脚本，主程序退出后再替换（杀软误报需在发布说明中提示）。
- **节奏**：R3 的 toast 组件是 R2 确认框的前置，W1 先出最小可用版；契约测试网让三批发布都可回归兜底。

### 5.3 设计 / 用户版

- **体验主线**：「AI 正在对我电脑做什么」随时可答——确认框（操作/路径/影响三要素）、熔断暂停态（已花费/预算/三选项）、toast 三态分离（成功/警告/错误）。
- **成本叙事**：会话头部实时「约花费 ¥X」+ 发送前预估 + 1113 人话提示——把隐藏的省钱能力变成可见的产品性格。
- **不变的东西**：专业开发工具调性（高信息密度、深色优先、等宽字体承载数据）延续已完成的 UI 重设计；本次只加状态层，不改视觉语言。
- **更新体验**：v1.2.1 起启动检查→轻提示→更新说明→一键重启，结束「手动查 release」时代。
