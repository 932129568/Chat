TL;DR——全部迭代内容合入单一 v1.8.0，分四个内部里程碑（M1 地基 / M2 能力 / M3 放权 / M4 信任）。 契约零漂移打法：build_tools 加 include_agent 参数（默认 False 逐字节不变）+ 约 28 个新 js_api 全进 _V12_EXTRA 隐身 + 新配置全独立文件（software/hybrid/memory/search_cache）。 新增 8 个后端 service + 6 个前端模块 + prompts/ 目录，改 10 个既有模块。 最硬的两条实现纪律：① 浏览器提取结果走 pywebview js_api 回调（禁 evaluate_js 返回值——外部站 CSP 会失败）； ② guard 判定链重构为 deny → allow_rules → task_grant → op 档位 → 确认五层。

5. 主要执行流程

【Plan-Act 主循环】 用户发送 → hybrid.classify → understand（本地 5s；超时→云端；再失败→透传） → plan_service.propose → 计划卡（本地草稿；complex→云端） → 用户批准/编辑/拒绝 ──（L2 授权中+全 low 风险→自动批准） → Act：逐步执行，每步过判定链；validation 失败→reformulate ≤2→blocked → Reflect：hybrid validate（本地 3s）→ verdict+confidence；<0.7→云端复核/补做 → Deliver：摘要+回滚链接+trace_id 落审计 【browser_search（dual-LLM-lite）】 agent → browser_search → cache 命中直返（≤300ms） → adapters.build_url → search_browser.load_url → wait_selector 轮询（≤8s） → 页面 JS 抽原始结果 → window.pywebview.api.on_page_data(json) 回调 ← 禁 evaluate_js 返回值 → 本地读取器（hybrid understand）：schema 约束结构化（禁祈使句/禁工具名样式） → 过滤（域名黑白/时效/必含词/URL 归一去重/重排）→ extract=full → browser_open Top N → 注入包裹：provenance 分隔 +「UNTRUSTED DATA」标记 → cache+audit → 降级：窗口超时→urllib 兜底 / 验证码特征→面板人工接管 【software_call】 resolve（未装→人话引导，不自动下载）→ schema 校验（失败→错误+示例回显自校正） → 判定链（dangerous→always）→ cli 沙箱执行 / gui ShellExecute+FindWindowW 核验（≤10s）/ uri → 结构化结果+错误人话（git/ffmpeg 码表）→ audit 【检查点】plan approved → git 仓库？stash create 记 ref : 复制声明文件至 checkpoints/（≤200MB/500 文件） → rollback：清单→uiConfirm→恢复；保留最近 3 份
